# T-001 — Reconcile the private pasted-job journey

Status: proposed  
Owner: unassigned  
Branch/PR: —

## Why this matters

Students should be able to paste a job, save it privately, and return to it. A preview that looks saved but disappears does not deliver that outcome.

## Verified starting point

`src/app/(student)/jobs/PasteJobForm.tsx` previews a parsed posting. `job-api-client.ts` disables private saving; `src/app/api/jobs/import/route.ts` and `jobs/[id]/route.ts` lack adapters and fail closed. A separate `src/app/api/jobs/route.ts` can insert a private job directly. The flows conflict. Live Supabase migration/deployment state is UNKNOWN.

## Plan and review

Trace the form, `JobDraftSchema`, both import routes, job reads and SQL RLS. Choose and document one path; do not merely flip the UI flag. Product: a persisted, understandable result after reload. Data: owner derived from verified auth, private by default, other accounts denied. Verification: two fictional users, failed DB/auth states, and fixture smoke.

## Acceptance checks

- [ ] A signed-in user pastes a job and receives a saved private posting, then reloads and can read it.
- [ ] Another user and an unauthenticated browser cannot read that posting.
- [ ] Invalid input and DB failures produce clear errors without an invented saved state.
- [ ] Unverified source/deadline are not presented as verified.
- [ ] Conflicting `/api/jobs` and `/api/jobs/import` behaviors are reconciled and documented in `docs/contracts.md` and `docs/demo-claims.md`.
- [ ] Focused tests, typecheck, unit tests, build and relevant browser tests are recorded with results.

## Out of scope

Live web search, applying to an employer, and automatic deadline verification.
