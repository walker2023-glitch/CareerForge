# T-002 — Make profile saves atomic and test isolation

Status: blocked
Owner: Codex
Branch/PR: `feat/t002-atomic-profile` / PR #3 (stacked on T-001 / PR #2)

## Why this matters

Student facts are the evidence for later résumé output. Saving the profile but losing the facts can leave a misleading source of truth.

## Verified starting point

`src/app/api/profile/route.ts` checks `expectedUpdatedAt` then updates `profiles`, deletes existing `student_facts`, and inserts replacements as separate calls. If a later step fails, earlier writes may remain. The profile page has a fictional fixture mode; applied database state and two-account browser checks for this fork are UNKNOWN.

## Plan and review

Product: show saved facts after reload. Data: use a transaction or narrowly scoped RPC plus RLS, and enforce the expected-version check at the write boundary. Verification: injected failure, stale writer, foreign fact IDs and two accounts. Align `src/contracts/student.ts` and migrations if changed.

## Acceptance checks

- [x] Profile and facts commit together or neither changes.
- [x] A stale update returns a conflict without overwriting another change.
- [ ] An authenticated student cannot change another student's facts; signed-out requests fail.
- [ ] Saving and reloading through UI shows the same facts in an isolated test database.
- [x] Contracts, feature state and focused test results are updated.

## Out of scope

New profile fields and AI generation.
