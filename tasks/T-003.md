# T-003 — Connect evidence-backed résumé generation and edits

Status: proposed  
Owner: unassigned  
Branch/PR: —

## Why this matters

CareerForge should help a student tailor an application without inventing experience or silently losing edits.

## Verified starting point

`src/app/(student)/match/[id]/page.tsx` displays a fictional sample. The generation and own-version handlers in `src/app/api/resume/` have no connected persistence adapter or model caller. `src/contracts/resume.ts` defines the intended shape; deployment and provider credentials are UNKNOWN.

## Plan and review

Product: show the source fact behind each proposed bullet and allow editing/reload. Data: authorize job and facts, create an immutable generated payload/fact snapshot, allow only student-edited text to change, protect AI credentials. Verification: no evidence, prompt injection in job text, provider failure, another user's resume ID and reload.

## Acceptance checks

- [ ] Only a signed-in student with an authorized job can request suggestions.
- [ ] Every generated claim has a valid source fact reference; unsupported metrics are rejected or removed.
- [ ] A student can edit and reload their own saved version; generated evidence remains immutable.
- [ ] Other accounts cannot read/edit that version; provider or database failure returns a truthful error.
- [ ] UI, contracts, feature evidence and focused tests agree with observed runtime behavior.

## Out of scope

PDF export, application submission, live job search and invented hiring scores.
